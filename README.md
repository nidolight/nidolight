### 👋 About Me

**DB와 네트워크 병목을 줄이는 백엔드 엔지니어**

자동화 창고 관리 시스템부터 실시간 스트리밍 플랫폼, 외식업 주문 관리까지 다양한 도메인에서 인프라를 설계하고 운영해왔습니다. 

문제를 볼 때 **데이터가 어디서 막히는지** 먼저 봅니다. RDB 중심의 작업 큐를 Redis Sorted Set으로 옮겨 12배 성능 개선을 이루었고, 매 요청마다 DB에 접근하던 세션을 캐시로 옮기며 CORS 문제까지 해결했습니다. 선택에는 항상 측정이 뒤따릅니다.

6인 프로젝트에서는 팀장을 맡아 회고의 문제를 진행 방식 변경으로 풀어본 경험이 있습니다.

### 🎯 Key Projects

#### 1️⃣ **물류 자동화 지능형 창고 관리 시스템** · 삼성 SDI 연계
**2024.03 ~ 2024.05 (3개월) · 6인 팀 팀장 · 백엔드/DB 설계**

> 뱅크 사이를 오가는 크레인의 작업 지시(커맨드) 스케줄링 문제를 해결

**판단:** RDB 중심 작업 큐는 조회마다 정렬/인덱스 갱신이 필요했습니다. 갱신·조회 빈도가 높아 **Redis Sorted Set**을 선택하고, score를 `-(우선순위 × 10⁹) + 등록시각`으로 설계해 정렬 없이 우선순위와 선착순을 동시에 만족시켰습니다.

**결과:** 
- Redis 왕복을 Pipeline으로 통합 → **500건 기준 18.9ms → 1.6ms (약 12배 개선)**
- 부하 시 지연 편차도 3.8배 → 1.1배로 안정화
- 통합 테스트에서 입고 포트 충돌 문제 발견 및 해결

**팀 운영:** 회고의 "알고리즘 계산이 느려 회의가 멈춘다" 문제를 파악하고, 시뮬레이터 우선 완성 → 눈으로 검증하는 방식으로 변경

#### 3️⃣ **실시간 미디어 버스킹 스트리밍 플랫폼** · SSAFY 프로젝트 우수상
**2024.01 ~ 2024.02 (2개월) · 4인 팀 · 배포 인프라 전담**

> 거리 공연을 실시간 중계하고, 관객이 지도에서 공연을 찾아 시청·소통하는 플랫폼

**판단:** HTTPS + WebRTC를 동시에 지원하는 배포 환경을 팀 내에서 유일하게 구축 가능했습니다. 2개월 일정을 고려해 배포를 먼저 올려, 개발 중에도 항상 실제 서버에서 확인할 수 있도록 했습니다.

**결과:**
- Nginx Let's Encrypt HTTPS + 리버스 프록시 구성
- coturn TURN 서버로 NAT 통과 해결
- Redis로 세션 정보 캐싱 → DB 접근 감소 + CORS 문제 동시 해결
- 클론·빌드·실행을 한 번에 처리하는 배포 스크립트 작성 → 팀원 누구나 배포 가능
